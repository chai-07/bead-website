# 2026-11-06 移动端抽屉大改（index.html）

用户反馈手机端抽屉问题，本轮在 `index.html` 做了移动端（body:not(.force-desktop) 与 body.layout-mobile 两处，规则需同步改）抽屉重构：

- **结构**：抽屉顶部加真实拖拽条 `.sheet-grip`（含 ✕ 关闭按钮 `.sheet-close`）。**注意：曾加过全局横滑分类标签栏 `.cp-tabs`/`showCpGroup`（按 data-grp 切分组）被用户否决——用户要的是"整体布局不动"，仅「图像增强」组内部做按钮→滑块二级。** 现已撤掉 cp-tabs，恢复 openSheet 的"按 grp 显示对应组"原逻辑。
- **图像增强组二级改造（用户真实需求）**：`data-grp="enhance"` 组内，8 个滑块（深色归一/黑色阈值/伽马/饱和度/对比度/亮度/锐化/降噪）不再一次性摊开；改为 `.enh-btns` 按钮栏（横滑 chips：深色归一/黑色阈值/伽马/饱和度/对比度/亮度/锐化/降噪）+ `.enh-panels` 包裹各 `.enh-row[data-row=id]`。移动端 `.enh-row{display:none}`、点 `.enh-btn[data-target=id]` 由 JS 事件委托切 `row.style.display`（block/none）并 toggle `.active` 高亮；桌面端 `.enh-btns{display:none}`、`.enh-row` 默认显示（保持原样）。滑块 input id 与 value-display 全部保留，resetParams 等不受影响。
- **不变暗/不挡画布**：scrim 改为 `background:transparent; pointer-events:none`（z125），画布保持明亮；抽屉 z-index 提到 130（高于原图浮窗 z120）。关闭靠 ✕ 或再次点击触发按钮（toggle）。
- **尺寸**：control-panel `bottom:calc(144px+...)`、`height:54vh`、`max-height:calc(100vh-196px)`；review-panel `top:calc(52px+...)`，避开顶部/底部栏。center-column 留白提到 150px、float-original bottom 提到 150px 以避让可能换行的 mid-bottom。
- **拉伸 bug 修复**：旧 CSS 给抽屉 `height:auto!important`，导致 JS 内联 `style.height` 被压制、拖拽无效。现 resize 用 `panel.style.setProperty('height',h+'px','important')` 覆盖；grip 用 sticky 固定在滚动容器顶部，pointer 事件拖拽改高度（bottom 抽屉向上长、top 抽屉向下长）。
- **mid-bottom**（显示原图/画布缩放/操作）保持 `overflow:visible; flex-wrap:wrap`（不横滑）、fixed。
- 双指缩放仅在桌面端生效（移动端用 缩小/适应/放大 按钮），pinch guard 在 handler 内判断 force-desktop。

注意：每次改移动端布局要同时改 `body:not(.force-desktop)` 媒体块和 `body.layout-mobile` 块，否则两种手机入口表现不一致。

## 项目结构重构（同日晚）
用户嫌 index.html 单文件内联 CSS+JS（2436 行）太混乱，已按标准静态站点拆分：
- `index.html`：仅保留 HTML 标记 + `<link rel="stylesheet" href="css/style.css">` + 末尾 `<script src="js/data.js"></script><script src="js/app.js"></script>`（data 先于 app 加载，保证全局配色变量可用）。
- `css/style.css`：原 `<style>` 全部内容（桌面+移动两套规则）。
- `js/data.js`：纯配色数据——`MARD_COLORS`/`PERLER_COLORS`/`HAMA_COLORS`/`ARTKAL_COLORS` 四套色板 + `BRAND_PALETTES` 映射（全局 var，供 app.js 引用）。
- `js/app.js`：其余全部逻辑（图像增强/量化/取色/画布/抽屉交互等）。

注意事项：未引入构建工具/ES module，沿用经典 `<script>`（非 module）以保证原有 `onclick="..."` 内联处理器能找到全局函数；无外部库、无本地图片资源（#originalImage 由程序用 dataURL 赋值）。改结构时若要用 ES module 需先把内联 onclick 改为 addEventListener。

## 手机端/电脑端独立拆分（同日夜，最终结构）
用户要求"选择页单独 + 手机电脑拆开"，选"共用应用页+参数进入"方案。原单页应用（选择浮层 `#versionChooser` 内嵌 index.html，靠 `applyVersion` 给 body 加 `force-desktop`/`layout-mobile` 切换）已拆成独立选择页 + 共用应用页：
- **`index.html`** = 版本选择独立页（仅 `#versionChooser` 卡片 + 内联脚本处理选择与 localStorage"记住选择"，选中后 `location.href='app.html?mode=desktop|mobile'`；记住时加载即自动跳转）。样式走 `css/choose.css`。**不再含应用 DOM 与业务脚本。**
- **`app.html`** = 共用应用页（原 index.html 完整应用 DOM 去掉 `#versionChooser` 浮层）。`<body>` 默认 `force-desktop`，紧跟内联脚本按 `?mode` 立即切 class（避免闪烁）；`head` 同时引 `css/style.css` + `css/mobile.css`；脚本仍是 data→color→render→draft→review→export→ui 七个。两个"切换版本"按钮（`switchVersionBtn2` 桌面标题栏 / `switchVersionBtn` 手机顶栏）改为跳回 `index.html`。
- **`css/choose.css`** = 从 style.css 抽出的选择器样式（`#versionChooser` / `.vc-*` / `body.choosing`）。仅 index.html 加载。
- **`css/mobile.css`** = 从 style.css 抽出的手机版排版（`@media(max-width:1200px)` 内 `body:not(.force-desktop)` 块 + `body.layout-mobile` 块）。仅 app.html 加载。
- **`css/style.css`** = 保留桌面基础样式 + `body.force-desktop` 强制桌面块（已删选择浮层样式与 mobile 块）。
- **`js/ui.js`** 改动：`applyVersion('auto')` 改为按 `window.innerWidth<1200` 决定 desktop/mobile（确保宽屏拿到 `force-desktop`）；删除 `enterVersion`/`showVersionChooser` 与原来的选择 IIFE（逻辑已迁到 index.html）；新增启动 IIFE 读取 `?mode` 调 `applyVersion` 固定布局；`switchVersionBtn` 监听改为跳回 index.html。**坑：原"选择器+移动端绑定"曾是同一个大 IIFE（121-180 行），删开头 `(function(){` 时必须保留结尾 `})();` 或重包一层，否则括号不匹配（已踩过并修好）。**
